# TwitchDock.NET 1.0.0-rc.6

## English

The sixth release candidate of **TwitchDock.NET**, an independent .NET 8 / .NET 10 SDK for the Twitch API, EventSub, chat and authentication. **Updating is recommended for everyone using the EventSub WebSocket client.**

### Fix: EventSub clients no longer go offline on `session_reconnect`

When Twitch moved a session with a `session_reconnect` URL whose host differed from the configured endpoint, `RunAsync` ended with `JsonException`. In production this happened several times a week, and the host stayed offline until it restarted the client.

- With the default endpoint the client now follows any `wss://` host under `twitch.tv` on port 443. The host must be `twitch.tv` or end in `.twitch.tv`, so look-alikes such as `eviltwitch.tv` or `eventsub.wss.twitch.tv.evil.com` are rejected. URLs with user info are never followed.
- A custom endpoint, such as the Twitch CLI mock server, keeps the exact scheme, host and port comparison.
- A URL that is not allowed no longer stops the client. It is handled like a lost connection: the old socket is closed, and after a short backoff the client opens a fresh session on the configured endpoint and calls `onSession` with `resubscribe: true`.
- Such a URL is logged as a warning through the new optional `ILogger<EventSubWebSocketClient>` constructor parameter, with scheme, host and path only; the query, which can carry a challenge token, is left out. `AddTwitchDock` passes the container's logger.

The constructor change is source compatible; code compiled against rc.5 must be rebuilt. The release workflow requires the full test matrix, unit and contract tests on both target frameworks, Twitch CLI integration tests, package smoke tests, native AOT checks and the API-coverage gate.

This is a **prerelease**. Public APIs may change before 1.0.0.

### Get started

```sh
dotnet add package TwitchDock.DependencyInjection --prerelease
```

## Deutsch

Die sechste Vorabversion von **TwitchDock.NET**, einem unabhängigen SDK für **.NET 8 und .NET 10** mit Twitch-API, EventSub, Chat und Anmeldung. **Das Update wird allen empfohlen, die den EventSub-WebSocket-Client nutzen.**

### Korrektur: EventSub-Clients gehen bei `session_reconnect` nicht mehr offline

Wenn Twitch eine Session mit einer `session_reconnect`-URL verschob, deren Host vom konfigurierten Endpunkt abwich, endete `RunAsync` mit einer `JsonException`. In Produktion passierte das mehrmals pro Woche, und der Host blieb offline, bis er den Client selbst neu startete.

- Mit dem Standard-Endpunkt folgt der Client jetzt jedem `wss://`-Host unter `twitch.tv` auf Port 443. Der Host muss `twitch.tv` sein oder auf `.twitch.tv` enden; Nachahmungen wie `eviltwitch.tv` oder `eventsub.wss.twitch.tv.evil.com` werden abgelehnt. URLs mit Benutzerangaben werden nie verfolgt.
- Ein eigener Endpunkt, etwa der Mock-Server der Twitch CLI, behält den exakten Vergleich von Schema, Host und Port.
- Eine nicht erlaubte URL beendet den Client nicht mehr. Sie wird wie ein Verbindungsabbruch behandelt: Die alte Verbindung wird geschlossen, und nach kurzer Wartezeit baut der Client eine neue Session zum konfigurierten Endpunkt auf und ruft `onSession` mit `resubscribe: true` auf.
- Eine solche URL wird als Warnung über den neuen optionalen Konstruktor-Parameter `ILogger<EventSubWebSocketClient>` protokolliert, nur mit Schema, Host und Pfad; der Query-String, der ein Challenge-Token enthalten kann, wird weggelassen. `AddTwitchDock` übergibt den Logger des Containers.

Die Konstruktor-Änderung ist quellkompatibel; gegen rc.5 kompilierter Code muss neu gebaut werden. Vor der Freigabe verlangt der Workflow die vollständige Testmatrix, Unit- und Vertragstests auf beiden Zielplattformen, Twitch-CLI-Integrationstests, Paketprüfungen, Native AOT und die Prüfung der API-Abdeckung.

Dies ist eine **Vorabversion**. Die öffentliche API kann sich vor Version 1.0 noch ändern.
